# Fresh Market 后端接口使用说明（C端商品评价）

> 本文档面向前端开发，描述用户端商品评价的 2 个接口（提交 + 商品详情页分页查询）。**2026-09-09 实测通过**，示例为真实响应。
> 通用约定与《user端接口使用说明.md》一致：统一响应 `{code, msg, data}`、时间字段格式 `yyyy-MM-dd HH:mm`（无秒）、跨域走 dev server 代理。
> 我的评价、修改/删除等接口后续补充（见第 3 章）。

## 1. 鉴权

评价接口**需要登录**（`/user/**` 拦截）：

- 请求头：`authentication: <登录返回的 token>`（注意不是管理端的 `token` 头）。
- 未带/无效 token：**HTTP 401，响应体为空**。

## 2. 接口详情

### 2.1 提交商品评价

`POST /user/goodsComments/submit`（需 token，JSON，2026-09-09 实测）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| orderDetailId | number | 是 | 订单明细 id（评价入口在"我的订单-已完成"的某件商品上，取该明细的 id） |
| rating | number | 是 | 评分 1-5 星（整数，超出范围后端拦截） |
| content | string | 否 | 评价内容，最长 500 字 |
| anonymous | number | 否 | 是否匿名 0否 1是，不传默认 0 |

```json
{ "orderDetailId": 999101, "rating": 5, "content": "很新鲜，第二天就到了" }
```

成功响应（实测）：

```json
{ "code": 1, "msg": null, "data": null }
```

失败响应（业务失败均为 `code: 0`）：

| msg | 场景 |
|---|---|
| `"订单明细不存在"` | orderDetailId 无效 |
| `"订单不存在"` | 明细所属订单无效，**或订单不属于当前登录用户**（他人订单不可评） |
| `"订单完成后才能评价"` | 订单状态不是 5 已完成（含已取消订单） |
| `"该商品已评价，请勿重复评价"` | 该订单明细已提交过评价（含并发重复提交） |
| `"评分不能为空"` / `"评分最低1星"` / `"评分最高5星"` / `"评价内容不能超过500字"` | 参数校验失败 |

**提交规则**：

1. **评价挂在订单明细上**：一条明细（= 一件商品在某次订单中的购买记录）只能评价一次，数据库唯一索引兜底，重复提交即使并发也会被拦截。
2. **资格校验链**：明细存在 → 订单属于当前用户 → 订单状态为已完成（status=5），任一不满足直接失败（对应上表前三行）。前端建议只在"已完成"订单的明细上露出评价入口。
3. **goods_id / user_id / order_id 由后端自动回填**（取自订单明细与登录态），前端不传、传了也不生效——无法替他人或替未购买的商品刷评价。
4. 匿名只影响后续列表展示（显示为匿名用户），本版无查询接口，前端透传开关即可。
5. 评价提交后即为展示状态（status=1），无需审核。

### 2.2 分页查询商品评价（商品详情页）

`GET /user/goodsComments/page?goodsId=&page=&pageSize=`（需 token，2026-09-09 实测）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| goodsId | number | 是 | 商品 id（不传返回 `"商品id不能为空"`） |
| page | number | 是 | 页码 |
| pageSize | number | 是 | 每页条数 |

成功响应（真实示例，含商家回复的评价）：

```json
{
  "code": 1,
  "msg": null,
  "data": {
    "total": 1,
    "records": [
      { "id": 4, "rating": 3, "content": "橙子个头有点小", "anonymous": 0,
        "reply": "thanks for feedback", "replyTime": "2026-09-09 16:19",
        "createTime": "2026-09-09 16:18", "userName": "134205", "userAvatar": null }
    ]
  }
}
```

records 字段说明：

| 字段 | 说明 |
|---|---|
| id | 评价 id |
| rating | 评分 1-5 |
| content | 评价内容 |
| anonymous | 是否匿名 0否 1是 |
| reply / replyTime | 商家回复及回复时间，未回复时为 null（回复接口见管理端文档） |
| createTime | 评价时间 |
| userName | 评价用户昵称；**匿名评价固定显示"匿名用户"**（后端脱敏） |
| userAvatar | 评价用户头像；匿名评价为 null |

**查询规则**：

1. 只返回**显示中**（status=1）的评价，管理端隐藏的不会出现。
2. **匿名评价在 SQL 里脱敏**：userName 显示"匿名用户"、userAvatar 置 null，前端无需再判断 anonymous 字段处理昵称。
3. 按评价 id 倒序（最新在前）。
4. 评价可能为空列表（total=0、records=[]），前端注意空态展示。

## 3. 联调注意事项

- **已实现**：提交（2.1）、商品详情页评价列表（2.2）。**未实现**：我的评价、修改/删除、评价图片；管理端分页/回复/隐藏见《goodsComments管理端接口使用说明.md》。
- **只支持普通订单**：评价校验走 `orders` 表；秒杀订单（`seckill_orders`）暂不支持评价，后续如支持会另加说明。
- **不更新商品评分统计**：提交评价不会改动商品表的评分/销量等字段（当前 goods 表没有评分统计列），商品详情页如需展示平均分，等评分统计功能上线。
- `rating` 为整数；传小数/字符串数字以外的内容会触发参数校验或反序列化错误。
- HTTP 401 与 `code: 0` 是两类失败：401 是 token 问题（重新登录），`code: 0` 是业务/校验失败（按 msg 提示用户）。
