# Fresh Market 后端接口使用说明（管理端 AI 对话）

> 本文档面向前端开发，描述管理端**AI 对话**的 1 个接口（2.1）。后端通过 function calling 让大模型调用只读查询工具回答经营数据问题，模型**只能查、不能改**。接口于 **2026-09-07 实测通过**，示例为真实响应（answer 节选）。
> 通用约定与《goods和login接口使用说明.md》一致：统一响应 `{code, msg, data}`、跨域走 dev server 代理。

## 1. 鉴权

AI 接口**需要管理员登录**（`/admin/**` 拦截）：

- 请求头：`token: <管理端登录返回的 token>`
- 未带/无效 token：**HTTP 401，响应体为空**。

## 2. AI 对话（/admin/ai）

### 2.1 AI 对话提问

`POST /admin/ai/chat`（需 token，JSON）

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| question | string | 是 | 商家的问题，自然语言，如"今天卖掉了几个甜橙" |

```json
{ "question": "今天卖掉了几个甜橙？" }
```

成功响应（真实示例，answer 为节选）：

```json
{
  "code": 1,
  "msg": null,
  "data": {
    "answer": "今天（2026-09-07）甜橙没有销售记录，销量为 0 件，金额 0 元。",
    "toolTrace": [
      {
        "toolName": "query_goods_sales",
        "arguments": "{\"goodsName\":\"甜橙\",\"beginDate\":\"2026-09-07\",\"endDate\":\"2026-09-07\"}",
        "result": "{\"goodsNameLike\":\"甜橙\",\"beginDate\":\"2026-09-07\",\"endDate\":\"2026-09-07\",\"items\":[],\"totalQuantity\":0,\"totalAmount\":0}"
      }
    ]
  }
}
```

**data 字段说明**：

| 字段 | 类型 | 说明 |
|---|---|---|
| answer | string | AI 的最终回答，markdown 文本（可能含加粗/表格，建议按 markdown 渲染） |
| toolTrace | array | 本次回答背后实际执行的工具调用轨迹，按发生顺序排列 |
| toolTrace[].toolName | string | 工具名：`query_goods_sales`（商品销量）/ `query_goods`（商品多条件查询）/ `query_order_stats`（订单统计） |
| toolTrace[].arguments | string | 工具入参，**JSON 字符串**（前端展示需 `JSON.parse`） |
| toolTrace[].result | string | 工具执行结果，**JSON 字符串** |

**错误响应**：`{ "code": 0, "msg": "<原因>", "data": null }`，常见 msg：

- `问题不能为空` —— question 缺失或全空白
- `AI 服务调用失败，请稍后重试` —— 网络超时/大模型服务不可用
- `AI 服务返回错误：<服务端原因>` —— 鉴权失败、限流等（后端 API key 问题，联系后端）
- `AI 工具调用轮数超限，请换个问法或缩小查询范围` —— 问题过于复杂导致模型连续查询超过 5 轮
- `AI 未返回有效回答，请重试` —— 模型返回异常，直接重试即可

### 2.2 toolTrace 的用途

toolTrace 是回答的**数据来源凭证**：AI 被要求只依据工具返回的数据报数字。前端可用于：

- **展示"查询依据"**：把 arguments/result 渲染成可折叠的明细，增强商家信任；
- **审计**：回答里报了数字但 toolTrace 为空，说明模型没有查库（口径存疑），可提示用户重问。

一次提问产生 0~N 条轨迹：闲聊类问题 0 条；复合问题（如"甜橙销量 + 哪些商品库存不足"）通常 2 条起。

## 3. AI 能回答什么（能力边界）

后端注册了 3 个只读工具，AI 的能力=这三者的组合：

| 工具 | 能查 | 典型问题 |
|---|---|---|
| query_goods_sales | 按商品名（模糊）+ 日期范围查销量/销售额，普通订单与秒杀合并统计 | "今天卖掉了几个阳光玫瑰葡萄""上周车厘子卖了多少元" |
| query_goods | 按名称/分类/价格区间/状态/库存上限过滤商品，按价格或库存排序，最多返回 50 条 | "单价大于 20 元的商品有哪些""肉分类里库存不足 20 件的" |
| query_order_stats | 按日期范围统计订单量/有效单/取消单/营业额（普通+秒杀两渠道及合计） | "昨天的营业额""这个月取消了多少单" |

- **相对时间可用**："今天/昨天/这个月/上周"等由后端注入当天日期、模型自行换算；
- **数据口径**：销量/营业额只算**已支付且未取消**的订单（秒杀每单限购 1 件按件数计）；金额单位元；
- **只能查不能改**：没有下单/改库存/删商品类工具，让 AI"帮我下架某个商品"会被拒绝并说明只能查询；
- 超出三者范围的问题（如"哪个员工卖的最多"），AI 会如实说查不了，不会编造。

## 4. 联调注意事项

1. **耗时远长于普通接口**：真实调用大模型 + 数据库查询，实测单次 **5~40 秒**。前端请求超时建议 ≥60 秒，务必做加载态（如"AI 正在查询…"），等待期间禁止重复提交。
2. **回答非固定模板**：同一问题的措辞/排版（表格 vs 列表）每次可能不同，前端不要对 answer 做结构化解析，按 markdown 渲染即可；需要结构化数据的场景请走对应的管理端普通接口。
3. **模型行为是概率性的**：极少数情况下模型可能不查库直接作答（toolTrace 为空，见 2.2），或把"不足 20 件"理解为严格小于。关键决策不要只依赖 AI 回答，可在 toolTrace 里核对原始数据。
4. **本接口每次调用都计费**（大模型 API 按量付费），前端不要做输入防抖式的自动提问，仅在用户明确提交时调用。
5. 后端当前模型/密钥配置变更不影响本接口的请求/响应结构。
